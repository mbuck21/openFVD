# Maybe later

Ideas deliberately left out. Add here instead of widening a pull request. Each entry says what would trigger doing it.

## Added 2026-11-10 (the set-up session)

- **A GitHub Actions build workflow.** Not added: Actions minutes are scarce on this account and a Qt build on a Windows runner costs ten minutes or more per run. The local build works since 2026-11-10 (`tools/build-windows.sh`), so the workflow would be short: the `msys2/setup-msys2` action with the packages from `docs/building.md`, then that script, uploading `build/dist` as an artifact. Trigger: the owner wants a downloadable build, or a second contributor appears; then `workflow_dispatch` only, run by hand before a release, not on every push.
- **An automated baseline test:** a command-line mode or a small driver that loads a `.fvd`, writes the three exports and runs `tools/compare_exports.py` against `samples/baseline/`, so the check in `docs/testing.md` needs no clicking. The obstacle is that `track::loadTrack()` and the exporters call into the widgets (`trackWidget`, `gloParent`). Trigger: the first change to the physics or the exporters, or the second time someone does the comparison by hand.
- **lib3ds for the `.3ds` export on Windows** (decision record 0003). Three ways: build the 2008 source once per machine and point `libs.pri` at it; vendor its source (LGPL 2.1, about 25 C files) into the repository so `with3ds` just works; or replace the exporter with a format that needs no library (OBJ is plain text). Trigger: the owner wants a 3D model of a track out of FVD++.
- **Port the renderer to Qt 6** (`QOpenGLWidget`, `QOpenGLShaderProgram`, `QOpenGLBuffer`, `QOpenGLFunctions`; `renderer/glviewwidget.*`, `renderer/mytexture.cpp`, `main.cpp`). Qt 5.15 still builds the code and is in long-term support, so this is not needed to get going. Trigger: Qt 5.15 becomes hard to install, or a feature needs Qt 6.
- **Upgrade QCustomPlot** from 1.2.1 (2014) to a current 2.x: its API changed, so `ui/graphwidget.cpp` and `ui/graphhandler.cpp` would need edits. Trigger: a plot feature the old version cannot do, or a Qt 6 port.
- **A portable `.fvd` format** (explicit little-endian fields instead of raw structs and `QColor`), or a text or JSON sidecar. Trigger: a file saved on one platform fails to open on another, or a change to the model that would break the raw layout anyway.
- **Rewrite the NoLimits 2 CSV import and the `.nl2elem` export against the current NL2 format**; the code dates from 2016 and 2023. Trigger: an export that NoLimits 2 refuses.
- **Drop the Oculus Rift code** (`USE_OVR` blocks in `renderer/glviewwidget.*`, `shaders/oculus.*`): it targets the 2013 developer kit API. Trigger: it gets in the way of a renderer change.
- **Delete `core/secbezier.cpp.orig`** and the unused `sky/*.png` files. Trigger: the first pull request that touches those folders.
- **Fix the version string** in `main.cpp` ("v0.77") and the file-format version it writes. Trigger: the first release from this fork.
- **A review paid by the promotional API credits.** The Console's promotional credits cover the API and the Agent SDK but not Claude Code, which is what the two GitHub workflows run (decision record 0005). A separate workflow could call the API directly: fetch the pull request's diff, send it with the review prompt, post the answer as a comment. Simpler than the Claude Code review (no exploring the repository by itself, no inline comments at first). First step: one request from a workflow to prove the key is accepted for a plain API call. Trigger: the subscription's limits start to pinch, or the owner wants those credits used before they expire.
- **A macOS build on this fork.** A non-goal by the owner's word of 2026-11-10 (`docs/feature-requests.md`, FR-2). The `osx/` folder and the `macx` block of `fvd.pro` stay untouched and unmaintained, and are removed if they get in the way. Trigger: the owner asks.
